# Review Boards

Durable records from `review-board` sessions: an owner reviewing rendered figures, tables, or
slides on a local board, and an agent revising their sources, round after round, until the
owner has approved the current render of every item. Governed by
`Infrastructure/rules/review-board-rules.md`.

## Layout

```
records/review_boards/<project id>--<board id>/
  board.yaml          config: items, sources, render command, reviewers   written by the owner
  feedback.yaml       every status and note, append-only                  written by the board server
  ledger.yaml         renders, hashes, measurements, rounds, decisions     written by review_board.py
  rounds/round-NN.md  each round's plan, reasoning, and evidence           agent prose + generated blocks
  board.md            summary                                              generated by `summary`
  renders/rNN/        per-round snapshots                                  gitignored
```

The directory carries no date, and it is namespaced by the reviewed project's id, so two
projects with a board of the same name never share a directory. One board covers one set of
items (the figures of one brief, say, or one slide deck), and a project may have several.

## Single writers

Each file has one writer, which is what lets the history be trusted:

- **Reviewer notes are never edited.** `feedback.yaml` is written only by the board server.
  `round open`, `round close`, and `lint` compare it against `git HEAD` and fail if a
  committed note was changed or removed.
- **Statuses are computed.** Nothing stores a reviewer's current status; it is folded from
  their events. An approval counts only while the render it approved is still the current
  one, so a later change makes it stale rather than silently carrying it over.
- **Items and reviewers are retired, never deleted.** Set `retired: true` in `board.yaml`;
  notes that name them are permanent.

## What is committed

Commit everything except `renders/`, which `.gitignore` excludes. Snapshots can be large,
and a figure built from restricted data should not enter git history; the ledger keeps each
render's content hash and measurements instead. Boards are project memory:
`make template-reset` scrubs this directory back to this README before the template is
copied into a new project.

## Tooling

The scripts, rules, and tests that write these boards are mapped in
